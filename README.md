# XZT1118.github.io
name: daily-expense-ledger
description: 记录口语化的日常生活消费，并维护包含初始化、更正、日结和自然月月末账单的本地消费账本。当学生、上班族或家庭主妇报告消费、要求修改或删除消费记录、希望日结或请求月末账单时使用此技能。本技能仅记录支出，绝不记录收入。


每日消费记账

名称

daily-expense-ledger：面向学生、上班族和家庭主妇的日常支出记账技能。账本数据全部使用可携带的 Markdown 文件；所有读写必须使用 scripts/ledger.py，不得手动编辑账本表格。

默认将账本保存至 Agent 用户主目录的 ~/.daily-expense-ledger/，避免 Android 等设备中只读的技能安装目录导致写入失败。先运行 config show 查看实际账本目录。若 Agent 使用其他可写目录，优先通过 DAILY_EXPENSE_LEDGER_DATA_DIR 设置该目录，或在每次命令中传入 --data-dir /可写/目录。只有检测到可写的旧版技能目录账本时，才继续使用其 data/ 目录以兼容已有数据。

在 Android、System Claw 或其他受限设备上，首次使用前读取 references/mobile-runtime.md，按其中步骤确认 Python 能力、应用存储权限和账本备份位置。

核心任务

- 初始化并保存用户身份、默认币种和汇总语气。
- 记录、查询、修改和删除日常消费支出。
- 生成按日消费汇总，以及仅在自然月最后一天生成的月度账单。
- 持久化保存全部消费历史和月度汇总快照；不记录收入。
- 日结或月末账单生成后，询问用户是否同步至手机便签（通过 MCP notes_create_note创建笔记）。

触发场景

- 用户首次使用、要求设置或修改身份、默认币种、汇总语气。
- 用户以口语描述一笔消费，例如“午饭花了 18 元”“昨天坐地铁 12 元”。
- 用户要求更正或删除消费记录，例如“改刚才那笔”“删除那条咖啡消费”。
- 用户说出“日结”“今日账单”“今日汇总”及等效自然语言。
- 用户说出“月结”“月末汇总”“本月账单”及等效自然语言。

信息收集

初始化设置

首次调用技能时，询问用户身份：学生、工作党 、家庭主妇或者自定义身份；汇总语气：友善亲切 或 严谨；以及默认币种。用户未说明币种时使用 人民币。将用户所说的中文身份、语气和人民币表述映射为对应值；

询问格式如下：

    👋 你好！这是「随口记账」skill 的首次使用引导。
    
    这个工具帮你做两件事：
    - **随口记账**：每天记录、查询、修改和删除日常消费支出
    - **日结**：每天生成按日消费汇总
    - **月结**：仅在自然月最后一天生成的月度账单
    
    我需要了解一些信息来完成配置，请回复以下内容）：
    
    ———————————————
    
    1. 你的身份（我该怎么叫你？）
       例：学生、工作党还是家庭主妇等等
    
    2. 你喜欢我怎么跟你交流（语气）
       例：亲切友好、严肃认真、可爱贴心
    
    3. 你日常使用的货币种类？
       例：默认为人民币   
    
    ———————————————
    
    直接回复就行，格式随意，我能读懂的 😊



使用 config show 判断是否已初始化。

    python scripts/ledger.py init --identity student --tone friendly
    python scripts/ledger.py config show
    python scripts/ledger.py --data-dir /可写/目录 init --identity student --tone friendly

用户要求时更新设置：

    python scripts/ledger.py set-config --currency USD
    python scripts/ledger.py set-config --identity worker --tone strict

消费信息

从用户话语中提取金额、描述、日期、类别、币种和可选备注。日期默认使用亚洲/北京时区的当天，币种默认使用已配置的币种；类别不明确时设为 其他。类别使用 饮食、交通、购物、租房/房贷、娱乐、学习、医疗、其他；用户明确指定自定义类别时原样保留。

若缺少金额或用途描述，不得臆造，应继续追问(最多追问2到3次，明确金额和用途描述)。若用户指定历史日期，使用其日期；不得记录或修改为未来日期。

执行流程

1. 记录消费

使用 add 保存完整消费。成功后告知用户已保存的金额、类别、日期和记录 ID。

    python scripts/ledger.py add --amount 18.5 --description "lunch" --category food --note "with classmates"
    python scripts/ledger.py add --amount 12 --description "subway" --date 2026-07-20 --category transport

若脚本返回 DUPLICATE_CANDIDATE，展示该重复候选记录并请求用户确认；仅在用户明确确认后，才使用 --confirm-duplicate 再次执行。

2. 更正或删除记录

先使用 list 定位记录并在回复中保留记录 ID。仅在没有歧义时，将“修改刚才那笔”理解为本轮对话中最新创建的记录；否则询问用户要修改哪一笔。

    python scripts/ledger.py list --date 2026-07-21
    python scripts/ledger.py edit --id ENTRY_ID --amount 15 --description "breakfast" --category food
    python scripts/ledger.py delete --id ENTRY_ID

修改后若会形成重复记录，遵循与 add 相同的确认流程。

3. 生成日结

识别日结触发场景后运行 daily。允许用户通过 --date YYYY-MM-DD 请求指定历史日期的日结。

    python scripts/ledger.py daily

日结生成后，询问用户："是否需要将此日结添加到手机便签？"。待用户确认后，调用 notes_create_note，参数 title="{YYYY-MM-DD} 日结"、content=日结报告全文。以工具返回为准——成功才说"✅ 已保存到手机便签"；失败如实说明原因，不伪造成功。

4. 生成月末账单

识别月结触发场景后，先检查亚洲/北京时区的当天是否为当月最后一个自然日。若不是，只说明月度账单仅在月末可用，不运行月度命令。若是，先运行 daily，再运行 monthly。

    python scripts/ledger.py daily
    python scripts/ledger.py monthly

月度命令会将可替换的月度快照保存至实际账本目录中的 monthly_summaries.md。

月末账单生成后，询问用户："是否需要将此月度账单添加到手机便签？"。待用户确认后，调用 notes_create_note，参数 title="{YYYY}年{MM}月账单"、content=月度账单报告全文。以工具返回为准——成功才说"✅ 已保存到手机便签"；失败如实说明原因，不伪造成功。

信息冲突与任务状态

信息优先级

当多条信息可能冲突时，按以下优先级逐层裁决：

1. 用户显式指定 > 已配置默认 > 系统推断
   - 用户明确给出的金额、日期、类别直接使用；未指定时才回退到已配置默认值（币种、身份）；均未指定时使用系统推断（当天日期、"其他"类别）。
2. 当前输入 > 历史对话隐含信息
   - "改刚才那笔"指向本轮对话中最新创建的记录；若本轮有多次创建，以最近一次为准。存在歧义时先列出候选让用户选择，不得猜测。
3. 命令参数 > 环境变量 > 默认路径
   - 账本目录优先级：--data-dir > DAILY_EXPENSE_LEDGER_DATA_DIR > ~/.daily-expense-ledger/ > 旧版技能目录兼容模式。config show 输出实际生效的目录及来源。
4. 显式日期 > 默认今天；历史 ✅ / 未来 ❌
   - 用户指定日期时使用其日期；未指定默认亚洲/北京时区当天。允许历史日期补录；拒绝未来日期（含修改为未来日期），立即报错并说明原因。

任务状态

模型在对话中跟踪任务状态，确保每一步处于明确的阶段，不跳跃、不遗漏：

  状态  	含义                        	模型行为                                 
  等待信息	缺少金额或描述等必要字段              	追问用户（最多 2-3 次），明确需要补充的具体字段           
  等待确认	检测到重复候选、删除操作、MCP 同步等需要用户决策	展示候选/预览，等待用户明确确认（"确认""可以""执行"等），不自动继续
  执行中 	已发出命令，等待脚本或 MCP 返回        	不再重复发起同一操作，静待返回                      
  已完成 	操作成功返回                    	报告结果（含记录 ID、金额、日期等），状态流转至下一任务或结束     
  已失败 	操作返回错误或异常                 	如实报告失败原因，给出下一步选项（重试/修正参数/放弃）；不得口头声称成功

状态流转规则：

- 等待信息 → 执行中：用户补齐信息后立即执行
- 等待确认 → 执行中：用户确认后执行；用户拒绝则结束当前任务
- 执行中 → 已完成：命令或 MCP 返回成功
- 执行中 → 已失败：命令或 MCP 返回错误
- 已失败 → 等待信息 / 等待确认：根据失败原因决定是否需要重新收集信息或确认

重复执行与失败处理

幂等处理

- 添加消费：同日期 + 同金额 + 同描述（case-insensitive）视为重复。脚本返回 DUPLICATE_CANDIDATE 时，展示候选记录，等待用户确认后才加 --confirm-duplicate 执行。不得在用户未确认时自动跳过或静默去重。
- 修改消费：修改后若与另一条已有记录形成重复，同样触发 DUPLICATE_CANDIDATE，遵循与添加相同的确认流程。
- 日结/月结：同一天多次执行日结，每次重新计算并输出最新报告；月末账单重复执行时，monthly_summaries.md 中对应月份的旧快照被替换，不产生重复条目。
- 初始化：已初始化时 init 拒绝覆盖（除非 --force）；日常配置变更使用 set-config。
- MCP 便签同步：每次用户确认后创建一条新便签，不检查手机端是否已有同名便签。若用户多次确认会产生多条便签——在询问前可提示"今日已同步过，是否再次创建？"

工具未开放

- MCP 工具（如 notes_create_note）在当前运行环境中可能未注册或不可用。调用前不假设工具一定存在；调用失败时如实告知用户"当前环境不支持手机便签同步"，不得口头声称"已保存"。
- Skill 仅依赖 notes_create_note；notes_delete_note 和 notes_update_note 已知不可用——不在流程中设计对它们的调用。
- ledger.py 脚本本身不依赖 MCP，即使 MCP 全部不可用，本地记账功能仍完整可用。

权限不足

- 脚本写入 EACCES / 目录不可写：不反复重试同一目录。提示用户授予 Agent 存储权限，或使用 --data-dir / DAILY_EXPENSE_LEDGER_DATA_DIR 切换到可写目录。
- MCP 权限弹窗（短信/联系人/存储等）：本 Skill 仅使用 Notes Provider，不涉及高风险权限；若运行时触发系统权限弹窗，等待用户授权后继续，不得假设已静默授权。
- Android 受限设备：参照 references/mobile-runtime.md，首次使用前确认 Python 可用性和存储权限。

部分失败

当多步操作中某一步失败时，已完成的操作不回滚，逐项汇报：

- 日结 + MCP 同步：日结报告生成成功但 MCP 便签创建失败 → 先展示日结内容，再说明"便签同步失败：{原因}"。日结数据已保存，用户可稍后重试同步。
- 月结流程：daily 成功但 monthly 失败 → 日结结果保留，说明月度账单生成失败原因。若 daily 失败则不继续执行 monthly。
- 连续记录多笔：逐笔执行，每笔独立报告成功或失败；前一笔失败不影响后续记录。

返回结果不明确

- 脚本输出既是结构化文本又是人类可读报告，无机器可解析的结构化标记。模型应以脚本 stdout 内容为准判断成功/失败，不以 exit code 为唯一依据。
- DUPLICATE_CANDIDATE 是特殊的"中间状态"——不是失败，需要用户决策。
- MCP 返回结果以工具实际返回为准。若返回信息不完整（如无明确 success/error 标记），按保守原则处理：有确认性输出（如返回了 note id）视为成功；无输出或超时视为失败，提示用户去手机对应 App 核对。

MCP 工具依赖

工具不存在/未授权/调用失败时，不得伪造成功。

Notes Provider（同步日结/月末账单到手机便签）

  工具名              	用途               	关键参数         
  notes_create_note	将日结或月度账单保存为手机便签笔记	title、content

参数约定：

- title：日结为 {YYYY-MM-DD} 日结；月结为 {YYYY}年{MM}月账单
- content：完整的日结或月度账单报告文本（与命令行输出一致）

调用前必须先经用户确认（"是否需要添加到手机便签？"），确认后才执行；以工具返回为准，成功才说已保存。

规则边界

- 仅记录支出（用户输入中包含'卖''收入''赚'等收入信息时直接拒绝记录）；不得记录收入、预算、道德评判。
- 保留全部历史数据；不得批量清空或归档全部消费记录（用户在输入删除命令后，再次询问用户是否确认删除，待用户确认后使用 delete --id 命令删除对应）。
- 用户可使用默认币种，或使用 --currency 覆盖单笔消费币种。
- 月度报告必须按币种分别汇总；不得合并不同币种金额。
- 用户需要命令字段定义、数据结构或解析示例时，读取 references/commands.md。
- 同一账本目录一次只能由一个 Agent 进程写入；同步、卸载应用或清理应用数据前，应备份三个 Markdown 数据文件。

输出格式

- 记录成功：输出记录 ID、日期、描述、金额与币种、类别和备注（如有）。
- 日结：按已配置的身份和语气输出消费明细、各币种总额、分类小计、金额最高的类别以及简短的建议。
- 月末账单：在日结后输出自然月消费明细、各币种总额、分类小计、金额最高的类别、日均消费和消费最高日以及简短的建议。
- 异常或待确认：清晰说明缺失字段、未来日期、重复候选或未到月末的原因，并告知用户下一步需要提供或确认的内容。

版本迭代与更新

V1.0.0 — 基础功能（随口记账 + 日结 + 月结）

- 实现核心记账闭环：add（记录）、list（查询）、edit（修改）、delete（删除）。
